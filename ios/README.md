# WiiUDownloader for iOS

A SwiftUI port of [WiiUDownloader](https://github.com/Xpl0itU/WiiUDownloader). The
upstream desktop app is Go + GTK4; this port keeps the upstream Go core (download,
decryption, title metadata and file extraction) and binds it into Swift through
`gomobile`, replacing only the GTK UI with SwiftUI.

## Layout

```
ios/
├── mobile/                   Go wrapper package bound by gomobile (package mobile)
├── WiiUCore/                 Swift Package: Go façade + pure-Swift helpers
│   ├── Frameworks/           Mobile.xcframework (generated, git-ignored)
│   └── Sources/WiiUCore/
│       ├── Backend/          GoBackend: gomobile bridge & error mapping
│       ├── Download/         TitleDownloader façade over the Go backend
│       ├── Decrypt/          TitleFileTree façade over the Go backend
│       ├── Formats/          WUAPacker (.wua repacking, pure Swift)
│       ├── Titles/           Title database, region/category helpers
│       ├── Progress/         ProgressReporter, pause/cancel controller
│       └── Support/          WiiUError
├── WiiUDownloaderApp/        SwiftUI application
│   ├── Sources/              AppState, RootView, Browse/Queue/Tools/Settings
│   └── Info.plist            Generated by XcodeGen
├── scripts/build_mobile.sh   Build Mobile.xcframework via `gomobile bind`
├── scripts/fetch_title_db.sh Regenerate the bundled title database
└── project.yml               XcodeGen project definition
```

The core depends on Foundation, CryptoKit (for the WUA packer) and the generated
`Mobile` framework. The Swift façades keep the same public API the app already
uses, so only `TitleDatabase` and `AppState` mirror data across the boundary.

## Building

Requires macOS with Xcode (for the iOS SDK), Go and
[XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
# 1. Build the gomobile framework the core links against
go install golang.org/x/mobile/cmd/gomobile@latest
go install golang.org/x/mobile/cmd/gobind@latest
gomobile init
ios/scripts/build_mobile.sh

# 2. Generate and open the iOS app project
cd ios && xcodegen generate && open WiiUDownloader.xcodeproj
```

Then pick an iOS 16+ simulator or device and run the `WiiUDownloader` scheme.

## Notes

- The Nintendo CDN (`ccs.cdn.c.shop.nintendowifi.net`) serves plain HTTP, so the
  app declares `NSAllowsArbitraryLoads` in its Info.plist.
- Downloads, decryption and file extraction run in the unmodified upstream Go
  code. `.wua` repacking is the only Swift-side data path, because upstream has no
  WUA/ZArchive implementation.
- The bundled title database is decoded in Swift for UI filtering and mirrored
  into the Go backend so it can resolve title keys and names.
- Downloads use `.part` + `.resume.json` journals identical to upstream, so
  interrupted transfers resume instead of restarting.
- Downloaded titles land in `Documents/WiiUDownloader` by default (folder is
  exposed in the Files app).
